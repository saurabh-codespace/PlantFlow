# Asynchronous service contract (version 1)

Backend is Maven reactor `backend/pom.xml`, modules `platform-common`, `transport-service`, `fleet-service`, `analytics-service`. Java packages `com.plantflow.shared`, `com.plantflow.transport`, `com.plantflow.fleet`, `com.plantflow.analytics`. Each application scans its own package plus `com.plantflow.shared`. Identity is Keycloak, separate database. No cross-service database reads.

Common library (root owner) provides:

- `com.plantflow.shared.security.Actor(String username,String role)` with `from(Authentication)`, `dispatch()`, `requireDispatch()`, `requireRider()`.
- `com.plantflow.shared.ApiException` with conflict/forbidden/missing.
- `com.plantflow.shared.events.EventEnvelope(String id,String type,int schemaVersion,String aggregateId,long aggregateVersion,Instant occurredAt,String actor,JsonNode payload)`.
- `Outbox.publish(String type,String aggregateId,long version,String actor,Object payload)` MUST run inside transaction. It serializes an envelope and persists in local `outbox_event`. Background confirmed Rabbit publisher marks sent only after broker confirms, retries failures. Exchange `plantflow.events` (topic, durable). Routing key = event type. Publisher ensures infrastructure queues exist before sending. Common Flyway migration V100__messaging.sql creates outbox and inbox_event (event_id primary key); migration location classpath:db/common plus classpath:db/migration. Migration versions share one namespace in each database: new migrations must start above V100 (V101 onward), including business migrations; do not introduce V2 behind the applied common migration.
- `Inbox.first(EventEnvelope event)` must be called within consumer transaction, returns false if duplicate (insert event id atomically with ON CONFLICT DO NOTHING, PostgreSQL; test-compatible implementation supplied by root).
- Rabbit payload is JSON string (not Java serialization/type headers). @RabbitListener listeners accept String and use ObjectMapper.readValue(raw,EventEnvelope.class). Add @Transactional on listener; acknowledge after successful commit, retries then DLQ via common config. Validate type/schemaVersion in consumer. Queue constants: `plantflow.transport`, `plantflow.fleet`, `plantflow.analytics`. `@RabbitListener(queues="plantflow.fleet")` etc.
- Stateless OAuth2 JWT resource server; issuer, audience `plantflow-api`, realm roles ADMIN/DISPATCHER/DRIVER/EMPLOYEE. Identity username from preferred_username. No local passwords/session/CSRF. `/actuator/health` public minimal response. All APIs otherwise authenticated, role checks in services. Aspect for timing and sanitized audit metadata; never logs method args or JWTs.

Events:

1. `transport.assignment-requested`: aggregateId trip id, payload `{tripId,vehicleId,driverId,passengers,kind}`. Fleet consumes, atomically claims vehicle and driver rows, writes assignment in its DB, emits confirmed/rejected in same transaction. Assigning same trip is idempotent. Invalid resources/capacity/busy/maintenance -> rejection event (normal domain failure, not poison message). Replies preserve request aggregateVersion in envelope for correlation.
2. `fleet.assignment-confirmed`: payload `{tripId,vehicleId,vehicleLabel,capacity,driverId,driverName}`. Transport consumes, changes ASSIGNING -> ASSIGNED, emits trip-changed.
3. `fleet.assignment-rejected`: payload `{tripId,reason}`. Transport consumes, on-demand ASSIGNING -> REQUESTED, shuttle ASSIGNING -> CANCELLED; `assignmentError` persisted. May retry on-demand. Ignore stale replies based on assignment request version stored in transport trip.
4. `transport.trip-changed`: payload `{trip: <Trip API record>, eventType: "TRIP_REQUESTED|ASSIGNMENT_REQUESTED|TRIP_ASSIGNED|ASSIGNMENT_REJECTED|TRIP_ARRIVED|TRIP_IN_PROGRESS|TRIP_COMPLETED|TRIP_CANCELLED|SEATS_RESERVED|RESERVATION_CANCELLED|SHUTTLE_SCHEDULED"}`. Every change carries increasing aggregateVersion, including assignments and reservations. Analytics consumes snapshots into idempotent latest-state facts and event activity; fleet consumes only terminal trip snapshots to release allocation, always lock vehicle then driver in same order as allocation. Out-of-order snapshots must not resurrect old state; compare aggregateVersion. No event contains credentials.

Fleet APIs stay as docs/api-contract.md, owns vehicle & driver catalog and allocations. Driver usernames match Keycloak identity. Seed demo driver usernames driver, driver2, driver3 only in dev. Add admin/dispatcher POST `/drivers` `{username,name}` to register provisioned Keycloak driver identity (document operator must give DRIVER role). GET `/vehicles` and `/drivers` restricted dispatch/admin except GET vehicles can be all authenticated as frontend requires. Maintenance blocked while allocated.

Transport owns locations, trips, reservations. No app_user foreign keys (username comes from verified JWT). Trip view keeps prior fields plus `assignmentError` string nullable; ASSIGNING state added. Assignment HTTP returns 202 with Trip ASSIGNING; UI polls. No new cancellation while ASSIGNING; waits for fleet response. All IDs local numeric except usernames. Shuttle assigned time set only on fleet confirmation. Vehicle capacity and driver/name copied from confirmed event to trip. Resource release occurs asynchronously after terminal event; UI reflects it after next refresh.

Analytics owns trip_fact and activity tables, consumes trip-changed. GET analytics maintains prior shape except fleet counts from a fleet snapshot event if implemented, otherwise frontend joins live GET vehicles. Prefer implement `fleet.availability-changed` event `{fleetBusy,fleetAvailable,fleetMaintenance}` emitted on create/status/allocate/release and dev seed; analytics uses versioned aggregate `fleet` counter. Preserve prior analytics response fields. CSV safe escaping. Consumer persistent projection + inbox commit together.

Ports: Keycloak 8081, transport 8082, fleet 8083, analytics 8084; React shell 5173, remotes assigned by frontend owner. Postgres databases/users separate per service. RabbitMQ queues bind: transport -> fleet.assignment-*; fleet -> transport.assignment-requested and transport.trip-changed; analytics -> transport.trip-changed and fleet.availability-changed. Dead letter exchange plantflow.dlx and per-queue dead letter queues.

Each service has its own migration, properties, Docker build target and tests. Shared dependency groupId com.plantflow artifactId platform-common version 0.1.0; parent com.plantflow:plantflow-parent:0.1.0.
